# Contact Page Data Plan

## Objective

Define the Contact page content before implementation so the page can be rebuilt without relying on the legacy contact dataset.

## Final Content Model

The Contact page should use page-level metadata plus section-level JSON files.

Recommended files:

- `page.json`
- `sections/hero.json`
- `sections/routes.json`
- `sections/form.json`

## Section Responsibilities

### Hero

Purpose:

- set the page tone,
- make the contact purpose obvious.

### Routes

Purpose:

- define the ways someone can reach the company,
- separate enterprise, research, and operational inquiries when needed.

### Form

Purpose:

- gather structured inquiry details,
- keep the form fields minimal and relevant.

## Content Standards

- Keep the page direct and honest.
- Avoid fake support infrastructure.
- Use placeholders only where the implementation still needs shape.
